# 1.3.0 候选版验收记录

日期：2026-09-11。状态：本地验收通过，准备 Intel Mac 候选包；尚未正式发布 `v1.3.0`。

## 修复范围

基于对 1.2 候选提交 `720eeb7` 的独立复查处理以下九项缺陷，保留 1.2 的核心＋补充阅读和语义召回方案。

| 旧问题 | 1.3 处理与回归 |
| --- | --- |
| 部分来源失败的新文章被旧报告遮蔽，随后又被去重 | 展示已完整落盘的可用降级报告，并标明部分完成；恢复后没有新增仍保留该报告 |
| 小数、百分比、英文月份等变化误判重复 | 数字、单位、日期与政策状态保留实质签名，包含同 URL 与跨来源反例 |
| 重复启动误将正在抓取的任务标为失败 | 启动数据库前取得进程生命周期锁；真实双进程竞争、强退恢复与取消测试 |
| 编辑主题丢失停用来源绑定 | 已绑定的停用/归档来源保留，真实浏览器往返验证 |
| 移除最后来源静默扩展到全部网站 | 保留不可用绑定并阻止该主题抓取；主动清空时说明语义并确认 |
| 导入重新启用本机已移除预设 | 本机移除与编辑优先，预览和执行使用同一匹配规则 |
| 慢但正常的来源被提前报超时 | 前端验证预算 60 秒，覆盖后端处理时限；两条路径均用真实 16 秒延迟验证 |
| 当前来源故障、健康显示仍取旧报告 | 单独返回当前任务错误；终态重新获取状态与健康；历史来源名使用冻结快照 |
| 取消后未刷新旧报告提示及时间 | 无需刷新页面即可看到取消状态、保留报告和两次时间 |

补充边界：同秒任务顺序和备份往返；较新报告尚未写完、损坏、结构错误时的回退；安全合并导入不覆盖本机可用报告；旧版来源范围歧义的安全提示。

- 完整自动测试 **313/313 通过，40.95 秒**，Ruff 通过；保留 1.1/1.2 兼容用例，超过原 215 项基线。两个上游测试框架弃用警告不影响结果。
- 最终源码浏览器操作 **20/20 通过**，无外网请求、HTTP 失败、控制台或页面异常。两条慢来源验证实际耗时 16,302 ms 和 16,108 ms。
- 后端、浏览器与连续运行检查使用隔离数据和故障注入，不读取真实 Key，不调用真实 DeepSeek。
- 浏览器保留原有 14 条操作流，并新增 6 条 1.3 故障流程。

- 2026-09-11 在当前 Windows 网络下，24/24 预设的 HTTPS RSS 文档审计与实际 `FeedService.fetch_metadata` 均成功；返回文章有日期。网站可用性不能保证永久或所有网络一致。
- 30 次离线单实例任务覆盖正常、重复、AI 失败、来源失败、空结果和取消各 5 次；数据库重新打开 5 次，完整性、主题绑定和收藏保持。这不是多天挂机或真机实测。
- macOS Intel CI 必须再通过自动测试、浏览器流程、打包、ad-hoc 签名、应用启动及 DMG／ZIP／SHA-256 上传，才可交付候选安装包。

## 真机发布门槛

在 2019 Intel MacBook Air / Sonoma 14.7.7 上：

1. 先在旧版导出完整备份并退出旧应用，再用候选 App 覆盖“应用程序”中的旧 App。无需先装 1.2，可从 1.1 直接升级。
2. 核对主题、关键词、排除词、门槛、数量、来源绑定、启停、历史和收藏；Key 仍在同机钥匙串。
3. 检查首次启动生成 `before-upgrade-1.3.0.sqlite3` 安全快照，重复启动不会反复覆盖；原 1.2 快照保留。
4. 验证真实 DeepSeek 连接与 ESG 抓取。关键词仅命中 1 条且数量不足时仍应语义复核；观察核心、补充、重复、来源错误与预算统计。
5. 连续抓取检查近 7 天去重，取消后旧报告时间可辨认；再次双击应用不打断当前任务。
6. 检查 ZIP 单层解压、DMG 打开与拖入安装流程。仍为 ad-hoc 签名、未公证；首次打开可能需在“隐私与安全性”手动允许。

上述门槛通过后才打 `v1.3.0` 标签并正式发布，保留 `v1.1.0` Release。

## 已知限制

- 不能承诺零缺陷、永久稳定或强行凑满新闻数量。质量取决于来源覆盖、时效、相关性、门槛和 API 可用性。
- 仍只采集 RSS/Atom，不支持将普通首页作为 RSS，也不绕过付费或登录限制。
- 旧应用没有新的实例锁；覆盖安装前必须退出旧版，不能让旧版和 1.3 同时运行。
- 升级保留同机 Key；跨机备份永不携带 Key，收件人需自己配置。
- 归档来源可通过移除后的撤销恢复；长期独立“已移除来源”管理页尚未提供。
- 部分来源的人类访问参考页会拒绝自动化请求；中央社旧版权参考地址本次返回 404，RSS 抓取仍正常，可查阅其[官方 RSS 目录](https://www.cna.com.tw/about/rss.aspx)。这些参考页状态没有被冒充为 RSS 故障。
